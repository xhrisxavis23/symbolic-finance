# 사전등록 — 교사 자체의 경제성 (1단계 라벨 기준 · 2단계 정본 계약 기준)

작성 시각은 이 파일을 처음 커밋한 git 커밋 시각을 따른다.
**작성 시점에 이 실험의 코드는 한 줄도 없고, 교사 예측의 손익 수치는 하나도 계산하지 않았다.**
(0911 에서 같은 예측 파일로 R² 만 계산했다. 신호 규칙별 y_path 평균·원장 손익은 본 적이 없다.)

---

## 0. 왜 하는가

지시(2026-09-14 KST 15:06): **교사 모델의 성능을 R² 가 아니라 "수익이 나는가"로 먼저 따진다.**

증류 수식은 교사를 흉내 낸 것이다. 교사 자체가 정본 계약에서 벌지 못하면 수식이 벌 이유가 없다.
그런데 지금까지 **교사 자체의 손익을 한 번도 재지 않았다.**

| 사실 | 근거 |
| --- | --- |
| 교사 자체 비교군을 범위에서 뺐다 | `0910/PREREG.md:32` — "Catalog AST 실행기가 신경망 순전파를 직접 평가하지 못한다" |
| 교사 게이트에 경제성 항목이 없다 | `0902/sd/teacher/gate.py:21-22` — 상관 > 0.05, 체결확률 보정 오차 < 0.25, 역선택 부호 |
| R² 와 수익이 보는 곳이 다르다 | `0902/sd/labels.py` — `y_path ≈ −1 + (30초 BID1 상승폭)/(스프레드 + 23bp)`. 매수가 이익이려면 `y_path > 0`, 즉 분포의 오른쪽 꼬리. R² 는 전체 행의 제곱오차라 몸통과 변동 큰 종목(261780 한 종목이 평가 ① 변동의 47.8%)에 끌린다 |
| 진입 규칙이 교사의 손익분기점을 쓰지 않는다 | `0902/sd/compile/threshold.py:11` — 임계가 직전 100틱 분위수. 교사가 모든 틱에서 손실을 예측해도 상위 5% 면 산다. `y_path` 는 비용으로 나눈 값이라 "예측 > 0" 이 곧 "기대 순이익 > 0" 인데 이 기준을 쓴 적이 없다 |
| 라벨과 계약이 다르다 | 라벨: ASK1 즉시 매수 · 30초 뒤 BID1 매도 · 항상 체결. 계약: BID1 지정가 10초/100틱 대기 · 손절 −120bp · 추적 −30bp · 최대 900초 · 체결이 불리한 순간에 몰림 |

그래서 두 단계로 잰다. **1단계는 걸러보기, 2단계가 판정이다.** 1단계 결과와 무관하게 2단계를 돌린다(지시).

## 2. 1단계 — 라벨 기준 경제성 (저장된 예측으로, 재학습·재예측 없음)

### 2.1 입력

- `0911/groups/out/predictions.parquet` (T2M `pred_deeplob`, RDG `pred_ridge`)
- `0911/groups/out/mb_full/predictions.parquet` (T3D `pred_deeplob`)
- 행 = 테스트일 **유효 행**(라벨 마스크 참), 종목 안에서 틱 순서. 두 파일의 행 정렬은
  `0911/groups/paired_analysis.load_aligned` 와 같은 방식(종목·`y_path` 완전 일치)으로 확인하고, 다르면 멈춘다.
- 분위 규칙은 **유효 행 위에서** 직전 100행으로 계산한다. 정본은 모든 틱을 창에 넣으므로 2단계와 창 구성이 다르다(1단계의 한계로 적는다).

### 2.2 지표 (규칙마다)

- 신호 행 수, 신호가 한 번이라도 켜진 종목 수, 전체 유효 행 대비 비율
- **신호 행의 `y_path` 평균** = Σ(종목별 합) / Σ(종목별 행 수)
- 신호 행의 `y_path > 0` 비율 (30초 즉시 매수·매도가 수수료 뒤 이익인 비율)
- 기준값: 같은 평가 집합 **전체 유효 행**의 같은 두 값 ("아무 때나 산다")
- 구간: **종목 단위 부트스트랩 10,000회**(rng 시드 0) — 95% 와 **본페로니 99.583%**(= 1 − 0.05/12)

### 2.3 판정 (평가 ①, 규칙마다)

| 판정 | 조건 |
| --- | --- |
| **신호 부족** | 신호 행 < 1,000 또는 신호 종목 < 20 |
| **라벨 기준 이익** | 신호 충분 & `y_path` 평균의 본페로니 구간 **하한 > 0** |
| **라벨 기준 손실** | 신호 충분 & 본페로니 구간 **상한 < 0** |
| **판정 불가** | 그 밖 |

**한계를 미리 적는다:** 라벨 기준 손실이 곧 계약 기준 손실은 아니다. 계약은 BID1 지정가로 들어가 스프레드를 아끼는 대신 체결이 불리한 순간에 몰린다. 반대도 마찬가지다. 그래서 1단계는 판정이 아니라 걸러보기다.

### 2.4 서술 (판정 아님)

- 예측 보정표: 교사별 예측값의 전체 분위 10분할 + 상위 1% · 상위 0.1% 구간마다 평균 예측 · 평균 `y_path` · `y_path > 0` 비율
- 변동 상위 종목 261780 을 뺀 같은 표
- 평가 ② 의 같은 표

### 3.3 주입 방식 — vendor 파일은 한 글자도 바꾸지 않는다

재생 프로세스 안에서만 두 함수를 감싼다(워커는 fork 로 물려받는다).

1. `framework.data.load` — 워커가 지금 읽는 (종목, 날짜)를 기록한다.
2. `framework.contract.ExpressionRuntime.evaluate` — 교사마다 하나씩 정한 **표식 AST**(비교군이 쓰지 않는 구조)를 만나면 그 종목-일의 교사 점수 배열을 돌려준다. 그 밖의 식은 원래 함수가 계산한다.

분위 임계도 같은 `evaluate` 로 입력식을 계산하므로 교사 점수에서 만들어진다.

## 4. 사전 예측 (틀려도 고치지 않는다)

1. **ABS 규칙은 세 교사 모두 평가 ① 유효 행의 1% 미만에서 켜진다.** 안 본 종목 R² 가 0.01~0.02 라 예측값이 −1 근처에 몰려 있을 것이다.
2. **1단계 12개 규칙 전부 "라벨 기준 손실".**
3. **2단계 교사 계약 12개 중 "수익" 은 없다.** 12개 모두 total_net_bps < 0.
4. **같은 Q95 에서 T3D 가 나이브보다 의사결정당 덜 잃는다.**
5. ABS 계약이 거래 부족이 아니면, **체결당 gross 가 같은 교사의 Q95 보다 높다.**

## 6. 결과를 본 뒤 하지 않는 것

- 임계(0, 분위 격자)를 바꾸거나 새 임계(예: `score > 0.2`)를 더하지 않는다.
- 교사·종목·날짜·체결·청산·비용을 바꾸지 않는다.
- 판정 수준(본페로니, scorable 200, 신호 1,000행/20종목)을 바꾸지 않는다.
- "수익" 이 나온 계약이 있어도 봉인 날짜를 이 사전등록으로 열지 않는다. 여는 것은 별도 사전등록이다.
- 새로 시험하고 싶은 규칙이 생기면 **새 사전등록**으로 한다.
