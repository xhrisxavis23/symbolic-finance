## 왜

증류 수식은 교사를 흉내 낸 것이다. **교사 자체가 정본 계약에서 벌지 못하면 수식이 벌 이유가 없다.**
그런데 0902~0911 은 교사를 R² 로만 쟀고, 교사 자체의 손익은 한 번도 재지 않았다(`0910/PREREG.md:32` 에서 범위 밖으로 뺐다).

R² 는 수익과 다른 곳을 본다:

```
y_path ≈ −1 + (30초 BID1 상승폭) / (스프레드 + 23bp)

매수가 이익  ⇔  y_path > 0  ⇔  30초 안에 스프레드 + 23bp 이상 오른다   ← 분포의 오른쪽 꼬리
R²          =  전체 행의 제곱오차                                        ← 분포의 몸통
```

## 이 폴더의 규칙

- **코드베이스는 `../0902/` 다.** 0914 는 실행·기록만 담고 `sd` 와 vendor 프레임워크를 읽기 전용으로 쓴다.
  **vendor 파일은 바꾸지 않는다** — 교사 점수는 재생 프로세스 안에서 `framework.data.load` 와 `ExpressionRuntime.evaluate` 만 감싸 주입한다.
- 교사는 `../0911/groups/out/` 의 저장본을 그대로 쓴다. 재학습하지 않는다.
- **결과를 보기 전에 기준을 적고 커밋한다.** 사전등록 커밋 전에는 코드를 쓰지 않았다.
  실행 중 점검 기준(C1)이 잘못된 것을 발견해 **원문을 두고 부록 A 로 정정**했다 — 2단계 재생 전, 1단계 결과 열람 전.
- 봉인 날짜(`20260420` 이후)는 쓰지 않는다.
- 시각은 `TZ=Asia/Seoul date` 값만 쓴다.
