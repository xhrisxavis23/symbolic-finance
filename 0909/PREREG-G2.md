# 사전등록 G2 — 순환 논리 없는 새 게이트 설계

작성 시각: 2026-09-09. **설계 문서다. 아직 아무것도 실행하지 않는다** —
배관 확인(§6)만 작은 규모로 한다. 전체 실행은 검토·승인 후.

전제: `L0-REPORT.md`. E0 게이트(`0902/sd/e0/criteria.py`)는 교과서 법칙 5개가
이 데이터에서 참이라고 **가정**하고 만들어졌고, L0 이 그 가정을 직접 측정으로
검증한 결과 **L1·L5 는 참, L2·L3·L4 는 이 데이터에서 성립하지 않는다**
(L2 CV=0.704 vs 기준 0.15, L3 log-log R²=0.025, L4 예측 R²=0.335 vs 기준 0.85).
추가로 `judge_l2`·`judge_l3`·`judge_l4` 의 회귀 타깃이 SR 수식 자신의 출력이지
실제 `y` 가 아니라는 것도 밝혀졌다 — 게이트는 "형태가 교과서 법칙처럼
생겼는가"를 물었지 "그 형태가 데이터를 예측하는가"를 묻지 않았다.

G2 는 이 두 결함을 동시에 고친 새 게이트다: **텍스트북 상수 대신 데이터에서
직접 잰 기준**을, **자기참조 회귀 대신 실제 `y` 에 대한 표본외 예측력**으로
적용한다.

---

## 0. 가장 큰 위험 — 동어반복

> 데이터를 보고 기준을 만들면 통과는 보장되지만 아무것도 검증하지 못한다.

"이 데이터에 있는 관계를 기준으로 삼는다"를 순진하게 하면: 증류가 찾은
관계를 정답으로 정의 → 항상 통과. 이건 E0 가 텍스트북 상수를 가정했던 것과
증상은 다르지만 병은 같다 — **채점 기준이 채점 대상에서 나온다.**

G2 는 이것을 구조적으로 막는다. 세 가지 분리가 전부다:

| 분리 | 무엇을 막나 |
| --- | --- |
| **데이터 분리** — 참조 집합(R)과 증류 집합(D)이 서로소 | 증류가 자기가 본 데이터로 만든 답을 자기가 채점하는 것을 막는다 |
| **시점 분리** — 밴드(참조 집합의 부트스트랩 CI)를 증류 실행 **전**에 확정 | 증류 결과를 보고 기준을 사후에 맞추는 것을 막는다 |
| **방법 분리** — 참조 측정은 단순 회귀(선형/로그선형/구간별 조건부평균), 증류는 교사+SR | "정답을 만드는 방법"과 "채점받는 방법"이 다르므로, 증류가 참조 방법을 흉내 내 통과하는 것과 진짜 데이터의 관계를 찾아 통과하는 것을 구분할 여지가 생긴다 |

이 셋을 만족해도 **완전히 순환에서 자유롭지는 않다** — 아래 §5 에 남는 약점을
전부 적는다. 특히 "단순 회귀가 못 찾는 관계를 증류가 찾으면 오답 처리되는
문제"는 사용자가 미리 지적한 그대로이고, §2.4 에서 정면으로 다룬다.

## 1. 세 갈래 분할 — 참조 / 증류-적합 / 증류-선택

E0 는 종목을 적합(fit)/선택(select) 둘로만 나눈다(`sd.e0.split`). G2 는
**셋**으로 나눈다: 여기에 **참조(reference, R)** 집합을 추가한다. R 은
D(=fit∪select) 와 완전히 서로소다.

```
전체 우주(층화 6층)
  │
  ├─ 층마다 시드로 섞는다 (코드순 아님 — 아래 근거)
  │
  ├─ 앞 n_ref 개 → 참조 집합 R          ← G2 새로 만드는 것
  │
  └─ 나머지 n_distill 개 → sd.e0.split.split_symbols (그대로 재사용)
       ├─ 적합(D_fit)   ← SR 이 보는 유일한 데이터
       └─ 선택(D_select) ← run_law 의 기존 표본외 후보 선택(그대로 유지)
```

**R 은 증류 파이프라인의 어떤 단계에서도 등장하지 않는다** — 교사 훈련에도,
SR 적합에도, `run_law` 의 후보 선택(primary_index)에도 안 쓰인다. R 은
오직 (a) 밴드를 만들 때, (b) 증류가 이미 정해서 내놓은 단 하나의 primary
후보를 최종 채점할 때만 쓰인다.

### 1.1 왜 코드순이 아니라 시드 셔플인가

`sd.universe.slice_symbols` 는 "층마다 코드 오름차순 앞에서 n 개"를 쓴다
(재현성 근거로 문서화돼 있다, `universe.py` 주석). G2 는 R 과 D 를 가르는
분할에는 이걸 안 쓴다 — 종목 코드 순서가 상장 시점·거래소 구분과 상관될
가능성을 배제할 수 없고, "참조/증류가 코드 순서로 갈린다"는 배치 자체가
System적 차이를 만들 수 있다(예: 코드 앞자리가 낮은 종목이 오래된 대형주에
쏠릴 수 있다). 그래서 층 안에서 결정론적 시드(`G2_SPLIT_SEED`)로 섞은 뒤
앞부분을 R 에 배정한다 — 재현성은 유지하면서 순서 편향은 없앤다.

`sd.e0.split.split_symbols` 자체(D 안의 fit/select 분할)는 그대로 재사용한다
(이미 시드 기반 무작위 분할이라 이 우려가 없다).

### 1.2 서로소 보증

코드에서 **assert** 로 강제한다(방어적 프로그래밍 — `l0_measure.py` 의
자기검산과 같은 자세):

```python
assert not (set(R) & set(D_fit))
assert not (set(R) & set(D_select))
assert not (set(D_fit) & set(D_select))   # split_symbols 가 이미 보증하지만 다시 확인
```

셋 중 하나라도 겹치면 즉시 예외 — 조용히 넘어가지 않는다.

### 1.3 크기 (전체 실행용 사전 값 — 배관 확인은 훨씬 작게, §6)

| | 층당 개수 | 6층 합계 | 비고 |
| --- | --- | --- | --- |
| 참조 R | 20 | ≤120 | 반복 K-fold CI 를 안정적으로 내는 데 필요한 최소 규모(§3.1) |
| 증류 D (fit+select) | 24 | ≤144 | `split.DEFAULT_FIT_FRACTION=2/3` → 층당 fit 16/select 8 |
| **요청 총합** | 44 | ≤264 | E0 의 기존 실행(층당 15, 총 90)보다 크다 — 참조 집합이 추가됐기 때문 |

층 하나에 44개 미만이 있으면(가능성 낮음 — E0 가 층당 15로 90종목을 이미
확보했다) 있는 만큼만 쓰고 **경고를 명시적으로 남긴다** — 조용히 층을
비우지 않는다.

## 2. 게이트가 무엇을 묻는가 — A/B/C 검토

세 후보(A 재발견, B 일반화, C 부가가치)를 검토한 결과 **B 를 1차 판정
기준으로, A 를 진단(비판정), C 를 3중 비교로 채택**한다. 근거는 아래.

### 2.1 왜 B(일반화)가 1차 기준인가

이 프로젝트가 실제로 쓰려는 것은 "증류가 찾은 수식"이다. 그 수식이 실전에서
의미가 있으려면 **본 적 없는 종목의 실제 `y` 를 예측**해야 한다 — 이것이
정확히 B1 이 지적한 결함("게이트가 재는 것과 법칙이 주장하는 것이 다르다")의
반대다. E0 의 `judge_l2`/`judge_l3`/`judge_l4` 는 형태(구조)만 봤다. G2 의
1차 기준은 **실제 `y` 에 대한 표본외 R²** 다 — 형태가 아니라 예측력.

측정 대상: 증류가 `D_fit` 에서 적합하고 `D_select` 에서 고른 **primary
후보 하나**(기존 `run_law` 의 산출물, 손대지 않는다)를, **한 번도 보지 않은
R** 에서 실제 `y` 에 채점한다.

### 2.2 왜 A(재발견)는 판정이 아니라 진단인가

구조 일치(기울기 부호, 지수 범위 등)는 유용한 정보이지만 그 자체로는
예측력을 보증하지 않는다 — E0 의 L4 가 정확히 이 실패 사례였다("자기 자신에
대해 R²=0.981"이었지만 실제 예측 R²는 0.335). 구조가 맞는데 예측력이 없다면
그 "구조"는 우연이거나 사소한 것이다. 그래서 A 는 **B 를 대체하지 않고
보강한다** — B 로 통과한 후보에 대해 "그 예측력이 실제로 법칙이 말하는
그 관계(부호·형태) 때문인지, 아니면 다른 경로로 우연히 맞았는지"를 사람이
검토할 때 쓰는 부속 정보로 South.

구현: `criteria.py` 의 그리드추출 함수(`approximately_affine`,
`judge_l3`/`judge_l4` 안의 로그-로그 회귀·다중선형회귀 부분)를 **그대로
재사용**한다 — 그 함수들 자체는 "수식에서 기울기/지수/계수를 뽑아내는 도구"로는
멀쩡하다. 잘못된 것은 그 값을 텍스트북 상수와 비교한 것이었다. G2 는 같은
도구로 뽑은 값을 **참조 집합에서 잰 범위(CI)** 와 비교한다 — 판정에는 안
쓰고 보고서에만 남긴다.

### 2.3 C(부가가치) — 세 방식을 나란히 채점한다

`run_law` 는 이미 4트랙을 계산한다(`main`=교사증류, `no_distillation`=SR 이
실측 y 를 직접 봄, `no_dimensionless`, `uniform_off_manifold`). G2 는 여기에
**참조 집합에서 잰 단순회귀 자체**를 세 번째 비교 대상으로 추가한다. 셋
다 R 에서 채점한다:

| 비교 대상 | 무엇을 봤나 | 만드는 코드 |
| --- | --- | --- |
| **주 후보(main)** | 교사가 증류한 타깃 + SR, D_fit 에서 적합 | `run_law` 그대로 (기존) |
| **no_distillation** | 실측 y + SR, D_fit 에서 적합 | `run_law` 그대로 (기존) |
| **단순회귀 기준선** | 실측 y + 단순 회귀(L0 방법 그대로), D_fit∪D_select 에서 적합 | G2 신규(§3.2 와 같은 함수 재사용) |

셋 다 **같은 R, 같은 채점 함수(`weighted_r2`)** 로 잰다. 이게 (C)의 구현이다
— "증류가 단순회귀를 이기는가"를 별도 판정으로 두지 않고 **투명하게 나란히
보고**한다. 판정(B)과 분리한 이유는 §2.4.

### 2.4 사용자가 미리 지적한 구멍 — "단순회귀가 못 찾는 걸 증류가 찾으면 오답 되는 문제"

이 위험을 정면으로 다룬다. G2 의 1차 판정 기준(B)은 **참조 집합의 달성
가능한 R² 천장**(§3.1, 참조 집합 안에서 반복 K-fold 로 잰 표본외 R²) 과
비교하지, **참조 방법의 형태**와 비교하지 않는다. 이 구분이 핵심이다:

- 판정 대상: 증류 후보의 **실제 예측 R²**
- 비교 기준: 참조 집합에서 "그 데이터로 달성 가능한 예측력이 어느
  정도인가"의 **CI 하한** — 회귀가 선형이든 로그선형이든, 이 숫자 자체는
  "이 데이터 이 타깃에 얼마만큼의 잡히는 신호가 있는가"를 재는 것이지
  "선형관계여야 한다"고 요구하는 게 아니다.

그러므로: **증류가 참조 방법(선형/로그선형)이 못 찾는 진짜 비선형·교호
관계를 찾아 실제 R² 가 참조 천장보다 높게 나오면 → 통과이고, 오히려 특기할
결과로 보고된다**(§4.2 "천장 초과" 표시). 참조 방법의 형태를 강제하는
쪽은 §2.2 의 진단(A) 뿐이고, 그건 판정에 안 쓴다.

**그래도 완전히는 못 피한다.** 참조 천장 자체가 "단순 회귀로 잴 수 있는
신호"의 CI 이므로, 만약 진짜 관계가 단순 회귀로는 아예 못 잡는 형태(예:
국소적으로만 존재하는 관계, 부호가 바뀌는 관계)라면 참조 천장 자체가
낮게(혹은 CI 가 0을 포함하게) 나와 "존재하지 않는다"로 조기 배제(§3.3)될
위험이 있다 — 이 경우 증류가 그 관계를 찾아도 애초에 자격 검사(§3.3)를
통과 못 해 채점 테이블에 오르지 못한다. 이건 **완전한 해법이 없다** — §5-1
에 잔존 약점으로 남긴다. 완화책: 자격 검사 문턱을 0(평균보다 나은 예측)
이라는 최소한의 원칙적 기준으로 고정하고(임의로 높이지 않는다), 자격
미달로 판정된 법칙도 **점 추정치는 항상 보고**해 완전히 묻히지 않게 한다.

## 3. 구체적 절차

### 3.1 참조 천장 — 반복 K-fold CV (증류 실행 전, 밴드 확정용)

**무엇을 반복하나:** 참조 집합 R **안에서** "종목 단위 K-fold"를 반복한다.
증류는 전혀 관여하지 않는다 — 순수하게 "이 타깃이 이 데이터에서 얼마나
예측 가능한가"를 재는 것이다.

```
법칙마다:
  R 의 전체 (X, y, mask, symbol_id) 를 한 번만 조립한다
  (`sd.e0.targets.assemble` 재사용 — parquet 재읽기를 반복하지 않는다)

  REPEATS 회 반복:
    R 의 종목을 층 비율을 유지하며 K 겹으로 무작위 배정(반복마다 새 배정)
    K 겹 중 하나씩 held-out 으로 돌아가며:
      train = 나머지 (K-1)겹의 행 풀
      "단순 참조 모델"을 train 에서 적합 (아래 법칙별 정의)
      held-out 겹의 행에 그 모델을 적용해 예측
    K 겹의 예측을 전부 모아 하나의 풀에 대해 weighted_r2(실측 y, 예측, 가중치) 계산
    → 이 반복의 "표본외 R²" 하나
  REPEATS 개의 R² 값 → 2.5/97.5 백분위수 = 밴드[하한, 상한], 중앙값 = 점추정
```

`train`/`held-out` 은 항상 **R 내부의 분할**이다 — R 전체가 증류에게는
안 보이므로, 이 반복 자체는 "밴드를 만드는 계산"이고 사전등록 시점에
숫자 없이 절차만 확정한다. **밴드 숫자는 실행 결과이지 사전에 손으로
넣는 게 아니다** — 그래서 "실행 전 확정"은 절차·문턱(§3.3 의 0 이라는
숫자)에 대해서만이고, CI 숫자 자체는 R 을 실제로 돌려야 나온다. 이 순서
(밴드 계산 → 증류 실행 → 증류 결과를 밴드에 비교)를 스크립트가 강제한다
— 밴드를 계산하는 함수와 증류 결과를 읽는 함수를 서로 다른 시점에 호출하고,
증류 실행 함수는 밴드 값을 인자로 받지 않는다(참조할 수 없게).

### 3.2 법칙별 "단순 참조 모델" — L0 이 이미 검증한 정의를 그대로 쓴다

새로 발명하지 않는다. `l0_measure.py` 의 측정 정의(자기검산 통과, 검증됨)를
**적합→예측** 두 단계로 나누기만 한다 (L0 은 "전체에 대해 한 번에 적합"만
했다 — CV 를 위해 훈련/평가를 분리해야 한다):

| 법칙 | 적합(train) | 예측(held-out 에 적용) |
| --- | --- | --- |
| L1 | `book_imbalance` 구간별 조건부평균(40구간) | held-out 행의 `I` 값이 속한 구간의 train 평균을 그 행의 예측값으로 |
| L2 | 실측 `y` 를 `ofi_over_qbar` 에 **풀링(pooled) 단순회귀**(종목별 아님 — 예측 규칙은 새 종목에 적용돼야 하므로 종목 무관 기울기 하나가 필요) | `slope·x + intercept` |
| L3 | `log|y|` 를 `log|volume_over_qbar|` 에 회귀(criteria.judge_l3 처럼 σ 는 train 중앙값에 고정) | `exp(slope·log|x| + intercept)`, 부호는 train 에서 관측된 부호 분포로 복원(아래 주1) |
| L4 | 실측 `y` 를 (rv5,rv20,rv100) 에 다중선형회귀 | `coef · x + intercept` |
| L5 | `dt_prev` 로그구간별 조건부평균(50구간) → `criteria._fit_exponential`/`_fit_power_law` 중 train R² 더 높은 쪽 | 그 함수형에 held-out `dt_prev` 대입 |

주1(L3): L0 의 측정은 `|y|` 를 예측하는 것이었다(방향 정보 없음). 예측력
채점(R²)은 부호 있는 실측 `y` 와 비교해야 공정하므로, train 에서
`sign(y)` 와 `sign(volume_over_qbar)` 의 다수결 관계(둘 다 임팩트 법칙이
가정하는 방향, 즉 거래량 부호를 따른다고 가정)를 복원 규칙으로 쓴다. 이건
법칙이 원래 가정하는 부호 관계 자체이므로 새 가정을 추가하는 게 아니다.

전부 **L0 이 자기검산까지 마친 회귀 방법**이다 — 새 통계 기법을 도입하지
않는다. `weighted_r2`(재사용, `sd/sr/base.py`)로 채점한다.

### 3.3 자격 검사(existence check) — 판정 테이블에 오를 자격

법칙 하나가 §4 의 판정 테이블에 오르려면:

```
CI_하한(참조 천장 R²) > 0
```

**문턱은 0 — 유일하게 원칙적으로 정당화되는 값이라 조정하지 않는다.**
표본외 R²>0 은 정확히 "평균을 찍는 것보다 낫다"는 뜻이고, 그 이하이면
"이 데이터에 이 형태로 잡히는 신호가 없다"는 뜻이다. 0.05 나 0.1 같은
임의의 숫자를 고르면 그 자체가 "결과를 보고 기준을 정하는" 새 손잡이가
된다 — 그래서 안 쓴다.

자격 미달 법칙은 **판정에서 제외**하되 점추정치·CI 는 항상 보고한다
(§2.4 완화책). "제외됨"은 실패가 아니다 — "이 법칙엔 애초에 이 표본으로
잴 만한 신호가 없다"는 것이고, 이는 **데이터/타깃 정의에 대한 발견**이지
증류 방법에 대한 판정이 아니다.

### 3.4 증류 실행 — `run_law` 그대로, 새 산술 없음

```python
result = sd.e0.runner.run_law(law, D_fit, D_select, DATE, seed=SEED,
                               sr_niterations=25, sr_maxsize=20)  # E0 와 동일값
```

바뀌는 게 없다 — 교사 훈련, SR 적합, `primary_index` 선택(D_select 의 실측
y 로) 전부 기존 코드 그대로. G2 는 이 결과에서 **`result.tracks["main"].
primary_verdict` 의 `expr` 자체**(judge 함수의 `passed` 는 안 쓴다)와
`result.tracks["no_distillation"]` 의 primary expr 만 가져다 쓴다.

### 3.5 참조 집합에서 재채점

```python
score_main = sr.base.score_candidate(main_primary_candidate, names, X_R, y_R, w_R)
score_no_distill = sr.base.score_candidate(nodist_primary_candidate, names, X_R, y_R, w_R)
score_baseline = <§3.2 단순모델을 D_fit∪D_select 전체에 적합 후 R 에 예측> 의 weighted_r2
```

`X_R, y_R, w_R` 은 `sd.manifold.select` 로 R 에 on-manifold 선별·가중치를
적용한 것 — 참조 천장(§3.1) 계산에도, 여기 재채점에도 **같은 신뢰반경
철학을 일관되게** 적용한다(다르게 적용하면 그 자체가 비교를 왜곡한다).
보조로, on-manifold 필터 없이 R 전체(마스크만 적용)에서도 한 번 더 채점해
**"신뢰반경 밖에서 얼마나 무너지는가"를 참고용으로 남긴다**(판정에는 안
쓴다 — off-manifold 질의는 이 프로젝트에서 원래도 "H2 검증용"으로 다뤄지지
판정용이 아니다, `sd/manifold.py` 문서 참고).

### 3.6 구조 진단(A, 비판정)

```python
diag_main = criteria.judge_l2(main_primary_candidate.expr, names, X_R)  # L2 예시
```

`passed`/`ambiguous` 는 안 쓴다 — `slope_mean`/`slope_cv`(L2), `exponent`
(L3), `coefficients`(L4) 같은 **추출된 숫자만** 참조 집합에서 §3.2 방식으로
직접 잰 같은 통계량과 나란히 보고한다. 텍스트북 상수와는 아예 비교하지
않는다 — E0 밴드(`AFFINE_CV_MAX` 등)는 G2 어디에도 안 쓴다(오직 L0 의
직접 측정에서만 참고용으로 쓰였다).

## 4. 통과·중단 규칙

### 4.1 선결 조건 — 대조군(L1·L5)

L0 이 이미 "L1·L5 는 참"이라고 밝혔다. G2 자체의 측정 코드가 멀쩡한지
확인하는 데 이 둘을 다시 쓴다(L0 의 자기변호 위험 점검과 같은 논리,
`PREREG-L0.md` §4-2):

```
L1 또는 L5 가 자격 검사(§3.3)를 통과 못 하면(CI_하한 ≤ 0)
  → G2 의 참조 측정 코드 자체를 의심한다. 이미 참인 관계를 이 절차가
    못 찾는다면 절차가 고장난 것이다. 다른 법칙 판정에 앞서 이것부터 고친다.

L1·L5 둘 다 자격은 있는데 **주 후보(main)가 둘 다 미달**이면
  → "통제 거부권(control veto)" 발동. 증류가 이미 참인 걸로 아는 가장
    쉬운 두 법칙조차 실제 y 로 재채점했을 때 재현하지 못한다는 뜻이므로,
    다른 법칙의 결과와 무관하게 STOP. (E0 의 "L1·L2 동시 실패 거부권"을
    대체 — E0 의 L2 는 이미 L0 에서 "법칙 자체가 없다"고 밝혀졌으므로
    거부권 대상으로 부적절하다. L1·L5 는 L0 이 참으로 확인한 유이한 둘이라
    이 역할에 맞다.)
```

### 4.2 법칙별 판정 (선결 조건 통과 후)

각 법칙(자격 있는 것만, §3.3):

```
recovered  :=  score_main(R) >= CI_하한(참조 천장)
```

`>=` 이지 `>` 가 아니다 — 참조 천장의 **하한**(이미 보수적인 값)을 넘으면
충분하다는 뜻이다. 부가 표시:

- `score_main(R) > CI_상한(참조 천장)` 이면 **"천장 초과"**로 별도 표시
  (§2.4 — 실패가 아니라 특기사항, 사람이 표현식을 검토해 진짜 발견인지
  누출/우연인지 판단해야 한다는 뜻으로 플래그만 단다)
- `score_baseline(R) > score_main(R)`(단순회귀가 증류보다 낫다)이면
  **"부가가치 없음"**으로 별도 표시(§2.3 — 이것도 실패가 아니라 "이 법칙엔
  증류의 복잡도가 필요 없었다"는 보고)
- `score_no_distillation(R)` 과 `score_main(R)` 차이가 크면(예: 방향이
  다르면) **"교사가 해를 끼쳤다"**로 표시

### 4.3 집계 규칙

```
E' = {L2, L3, L4} 중 자격 있는 법칙 수
K' = E' 중 recovered 인 법칙 수

선결 조건(§4.1) 위반 → STOP (통제 실패 또는 측정 코드 의심)
E' == 0            → INSUFFICIENT_TARGETS
                      (L1·L5 외엔 이 표본으로 잴 신호 자체가 없다 —
                       증류를 판정할 수 없는 상태. PROCEED/STOP 이 아니다.)
E' >= 1, K' == E'  → PROCEED (자격 있는 법칙을 전부 재현)
E' >= 1, 0<K'<E'   → HOLD (법칙별로 원인 조사 — 어느 게 통과·실패인지
                      기록하고 실패한 것부터 본다)
E' >= 1, K' == 0   → STOP (자격 있는 법칙을 하나도 재현 못 함)
```

### 4.4 이 규칙의 근거

E0 의 "5개 중 3개 진행/2개 이하 중단 + L1·L2 동시실패 거부권"과 같은
정신(절대다수 요구 + 대조군 기반 조기경보)을 유지하되 두 가지를 고친다:

1. **분모(E')를 결과에 따라 정직하게 줄인다.** E0 는 5개 법칙을 전부
   고정 분모로 놓고 투표했는데, L0 이 그중 최대 3개(L2·L3·L4)엔 애초에
   잴 대상이 없을 수 있다는 걸 보였다. 존재하지 않는 법칙을 "실패"로
   세면 증류가 정말 못 찾은 것과 원래 없던 것을 못 가른다 — 그래서 자격
   검사로 분모를 먼저 정한다.
2. **거부권을 L0 이 검증한 대조군(L1·L5)으로 옮긴다.** E0 의 거부권
   법칙(L1·L2)은 계획서가 "원형 그대로"라 정한 것이지 실증적 근거가
   아니었다 — L2 는 이제 L0 에서 "법칙 자체가 없다"고 밝혀졌으므로 그걸
   거부권에 남겨두면 항상 걸리는 죽은 규칙이 된다. L1·L5 는 L0 이 실제로
   참으로 확인했으므로 "증류가 최소한의 진짜 신호는 찾는가"를 재는 대조군
   자리에 맞다.

`PROCEED`(K'==E' 전부)를 요구하는 건 엄격해 보이지만, E' 자체가 이미 "잴
가치가 있다고 확인된 것"만 남긴 뒤이므로 그중 하나라도 놓치면 그건 진짜
방법의 구멍이다 — 표본이 부족해서 통과 문턱을 못 넘은 게 아니라(그런
경우는 자격 검사에서 이미 걸러졌다), 실제로 존재가 확인된 신호를 증류가
못 찾은 것이기 때문이다.

## 5. 남은 약점 — 찾은 대로 전부

1. **§2.4 의 형태-편향.** 참조 천장이 선형/로그선형 방법의 달성 가능
   R² 이므로, 그 방법이 원리적으로 못 잡는 관계(부호가 바뀌는 관계, 국소
   관계 등)는 자격 검사에서 조기 배제될 수 있다. 완화(§3.3 의 0 문턱,
   점추정 항상 보고)는 있지만 완전한 해법은 없다.
2. **CI 폭·반복수(K, REPEATS)가 새 손잡이다.** 부트스트랩/CV 설계에
   본질적으로 딸린 자유도이고, 이 값을 결과를 안 본 상태에서 고정해도
   "왜 그 값인가"에 텍스트북만큼 강한 원칙적 근거는 없다(§6 배관 확인에서
   민감도를 최소한으로 점검한다).
3. **자격 검사의 2종 오류.** 진짜로 존재하지만 작은 신호(L0 의 L2 처럼
   평균은 양수인데 종목간 변동이 큰 경우)가 참조 집합이 작거나 시끄러우면
   CI 하한이 0 을 못 넘어 "자격 없음"으로 조용히 빠질 수 있다 — 이러면
   G2 가 원래보다 관대해 보이는 게 아니라 오히려 **분모가 작아져서** 도달
   가능한 PROCEED 문턱이 낮아진다(자격 있는 것만 전부 통과하면 되므로).
   이건 "게이트가 너무 쉬워진다"는 방향의 위험이라 명시해 둔다.
4. **on-manifold 선별(`sd.manifold.select`)을 그대로 물려받는다.** 그
   절차의 quirk(신뢰분위수 0.99, 꼬리가중치 공식 등)는 G2 가 재설계한
   게 아니라 E0 에서 그대로 가져온 것이다 — 그 절차 자체에 결함이 있으면
   G2 도 같은 결함을 물려받는다.
5. **"천장 초과"·"부가가치 없음"·"교사가 해를 끼쳤다" 플래그는 자동
   판정이 아니라 사람이 표현식을 봐야 하는 신호일 뿐이다.** 이게 남용되면
   "안 좋은 결과는 전부 사람이 재해석"하는 뒷문이 될 수 있다 — 그래서
   §4.2 의 기본 판정(recovered/not)은 항상 자동·기계적으로 먼저 나오고,
   이 플래그들은 그 위에 **추가로만** 붙는다(기본 판정을 뒤집지 않는다).
6. **참조/증류 3분할이 여전히 같은 날짜(20260316), 같은 우주에서 나온다.**
   레짐이 바뀌면(다른 날) 이 검증 전체가 다시 필요하다 — 봉인 홀드아웃을
   열 수 없으므로 이건 이번 설계로 못 푼다. 명시만 해 둔다.
7. **`no_distillation` 트랙과 `main` 트랙이 같은 D_fit/D_select 를 쓴다.**
   그래서 "교사가 해를 끼쳤는가"(§4.2) 비교는 깨끗하지만, 두 트랙 모두
   R 을 한 번도 못 본 것은 똑같으므로 그 비교 자체가 "누가 R 을 더 잘
   일반화하는가"의 통제 실험으로는 타당하다 — 이 항목은 약점이라기보다
   확인 사항으로 남긴다.

`G2-DESIGN-NOTES.md` 에 기록한다 — 설계 결함이 드러나면 위 절들을 고치고

계획:

- SR 백엔드는 `naive`(Julia 불필요, 이미 0902 에서 배관 검증용으로 존재)
  — PySR 자체의 정합성은 0902 가 11회 E0 실행으로 이미 검증했으므로,
  여기서 다시 확인할 대상은 **G2 가 새로 짜는 부분**(3분할·반복 CV·
  재채점)이지 PySR 통합이 아니다. 전체 실행에서는 PySR 로 바꾼다.
- 확인 항목: 서로소 assert 통과, `assemble` 1회 호출 후 인메모리
  재표집으로 반복 CV 가 실제로 도는지, `run_law` 산출물에서 primary
  expr 을 뽑아 R 에서 재채점하는 배선이 끊기지 않는지, 전체 소요시간이
  선형 외삽했을 때 "몇 분~수십 분" 범위에 드는지.
