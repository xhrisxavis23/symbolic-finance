## 3. 진단 A — 표본 크기 대비 교사 R² 곡선

**질문:** 학습 행을 늘리면 안 본 종목에서 R² 가 오르는가.

| 항목 | 설계 |
| --- | --- |
| 스크립트 | `scale/build_pool.py`(풀), `scale/sample_size_curve.py`(측정) |
| 학습 풀 | 저마찰층 × 3일 |
| 평가 | **중간마찰층의 안 본 종목**(같은 날, on-manifold 선별 20만 행 고정) — 평가 집합을 고정하고 학습 행만 바꾼다 |
| 크기 | 20만 · 50만 · 100만 · 200만 · 500만 · 1000만 |
| 모델 | 얕은 모델(CPU), DeepLOB(GPU) — 둘 다 병목 2, 구조 불변 |
| 조기 종료 | 평가 10 epoch 마다, 인내 10 |

**이 곡선은 종목 축 일반화다.** 날짜 축(다음 날)은 재지 않는다 — 그건 진단 B 와 본 실험이 한다.

**측정하며 드러난 함정 두 개 (기록):**

1. **잘림** — 첫 측정은 epoch 예산 300 이라 DeepLOB 4점 중 3점이 오르는 중에 끊겼다(하한값).
   예산 1500 으로 다시 재니 20만 행 R² 가 0.01453 → 0.01788 (+23%).
2. **조기 종료 부작용** — 50만 행이 이웃보다 낮았다(0.01405). 평가 곡선이 회복하던 중에 인내 10회가
   소진돼 멈췄다. **"조기 종료 걸림" 은 "수렴" 이 아니다.** 곡선 종료 후 이상 지점을 인내 30 으로 재측정한다.

## 4. 진단 B — 종목군 분석

**질문:** R² 0.015 는 "모든 종목에서 조금씩" 인가, "일부 종목군은 되고 일부는 무작위" 의 평균인가.
근거: LOBFrame(Briola, Bartolucci, Aste, *Quantitative Finance* 2025) — 같은 DeepLOB 으로 큰 틱 종목
MCC 0.26 유지, 작은 틱 종목 0.01.

### 4.1 종목군 정의 (`groups/symbol_covariates.py`)

- **틱은 표를 박지 않고 종목별 1~5호가 인접 간격의 최빈값**으로 정한다. 전체 파일 표본에서 호가 단위표와
  맞지 않는 5원 간격이 섞였기 때문이다(ETF 로 추정, 주식만 보면 판정 확신도 하위 5% 가 0.591).
- 1차 축 **상대 틱** = 스프레드 평균 틱 수 3분위 / 2차 축 **유동성** = 거래대금 3분위. 경계는 규칙으로
  미리 정하고 분포에서 기계적으로 뽑았다.
- 틱 판정 불확실(`tick_share < 0.5`) 38종목 제외 → **2,469종목, 종목군당 823.**
- 기존 마찰층과 상대 틱은 다른 축이다(순위상관 0.33). 틱과 유동성은 섞여 있다(−0.555) → 틱×유동성 9칸을
  보조로 본다.

### 4.2 분할과 학습 (`groups/group_run.py`)

```
                  20260316·17        20260318            20260319
학습 종목 1,647     교사·릿지 학습       —                  평가 ② (본 종목·안 본 날)
선택 종목   411     —                  조기 종료·릿지 규제    —
평가 종목   411     —                  —                  평가 ① (안 본 종목·안 본 날) ← 1차
```

- 종목 분할은 틱 3분위별 같은 비율, 시드 0.
- 교사 DeepLOB: 학습 200만 행(on-manifold 선별), epoch 상한 1500, **인내 30**(부록 D).
- 기준선 릿지: **같은 16스텝 윈도우 입력(304차원)**, 같은 학습 행·가중치. 규제 강도는 선택 종목에서 고른다.
- **0910 의 함정(층 효과가 기준선에도 똑같이 나타남)** 을 두 가지로 막는다 — 교사를 모든 종목군 섞어
  학습시키고, 모든 종목군에 릿지를 나란히 잰다.
- 평가는 테스트일 **유효 행 전체, 가중치 없음**(on-manifold 선별은 종목군 모집단을 바꾸므로).
- 평가 윈도우는 종목·날짜 묶음 단위로 잘라 만들고(윈도우는 세션을 넘지 않으므로 정확하다),
  예측은 50만 행씩 GPU 에 올린다(`predict_path` 는 입력 전체를 한 번에 올린다).
- 단계마다 저장하고 재실행 시 끝난 단계는 건너뛴다.

### 4.3 분석 (`groups/group_analysis.py`)

- 행 단위 R² (구간 평균 지표는 쓰지 않는다 — 0909 에서 법칙마다 2~109배 제각각 부풀림).
- 종목 단위 부트스트랩 1000회. 종목별 충분통계로 계산해 행을 다시 모으지 않는다.
- **선결 조건:** 예측은 고정하고 **종목 안에서 y 를 섞어** 같은 R² 를 낸다. 섞은 y 에서 R² 가 유의하게
  양수(CI 하한 > 0)인 칸이 있으면 판정하지 않는다(부록 E). 종목 안 섞기는 종목별 y 평균을 보존하므로
  예측이 종목 수준 차이만 타면 드러난다 — 0909 에서 이 교란을 잡은 방식이다.
- **이질성 있음:** 최선·최악 종목군 CI 가 겹치지 않고, 최선 하한 > 0, 최악 하한 ≤ 0 (부록 B·C).
- **본질 vs 모델 부가가치:** 릿지도 같은 최선 종목군에 같은 방향 기울기면 본질.

## 6. 지시 1 "3일 전체 학습" — 전체 배치로는 불가능하다

§5 실측대로 3일 저마찰층만 해도 1.75 TB 가 필요하다. **미니배치 학습으로 바꿔야 한다.**
이것은 모델 구조가 아니라 학습 절차의 변경이지만 **epoch 의 의미가 바뀌어**(지금 1 epoch = 경사 1회)
기존 전체 배치 결과와 직접 비교되지 않는다.

그래서 순서를 정했다 — **200만 행에서 미니배치가 전체 배치와 비슷한 R² 에 닿는지 먼저 검증**하고,
통과할 때만 3일 전체로 간다. 기준은 `PREREG-MINIBATCH.md` 에 결과를 보기 전에 적었다.

## 7. 기록 규칙 (재부팅·세션 중단 대비)

이 폴더에서 머신 재부팅 1회, 세션 중단 2회가 있었다.

- 긴 실행은 `setsid nohup` 으로 분리하고 PID 를 파일로 남긴다.
- **결과 파일이 갱신될 때마다 감시 스크립트가 즉시 커밋한다**(`scale/run_detached.sh`,
  `groups/run_detached_stage.sh`). 여러 감시가 같은 잠금 파일로 커밋 충돌을 피한다.
- 대용량 산출물(예측 parquet, 모델 가중치)은 `.gitignore` 로 제외하고 요약 JSON 만 커밋한다.
- **시각은 `date` 명령 값으로만 적는다.** 손으로 적은 시각이 7~25분 틀린 적이 있다.
