## 1. 입력 형태 간극을 어떻게 메웠는가

### 1-1. 문제

원 DeepLOB(Zhang, Zohren & Roberts, 2019)은 `(시간 윈도우 × 호가 레벨 ×
{가격,수량})` 텐서를 받는다. 이 파이프라인의 교사(`ShallowMLP`, `run_slice.py`
가 실제로 쓰는 경로)는 `X: (n, F)` — 한 행이 한 시각의 feature 벡터, 시간
축이 없다(`sd/ticks.py::feature_matrix`, `run_slice.py` S0~S1, 읽기만 했다).

### 1-2. 결정 — 윈도우 생성과 모델을 분리한다

`sd/teacher/window.py::make_causal_windows(X, window, session_ids=None)` 를
독립 함수로 뺐다. `DeepLOBCompact` 는 이 함수의 출력(`(n, window*n_features)`
평평한 행렬)만 받는다 — 윈도우를 스스로 만들지 않는다.

**왜 모델 안에 숨기지 않았는가.** `sd.manifold.select` 는 신뢰반경 밖 표본에
가중치를 주고, `max_samples` 를 넘으면 `rng.choice` 로 무작위로 골라 정렬한다
(`sd/manifold.py`, 읽기만 했다). 표집 **후**의 행렬에서 "바로 위 행"은 시간상
이웃이 아니라 무작위로 뽑힌 다른 시각(심지어 다른 종목)의 행일 수 있다.
모델이 자기 입력의 행 순서에서 윈도우를 만들면, 호출자가 표집 후의 `X` 를
실수로 넘겼을 때 **조용히 잘못 돈다** — 에러도 안 나고 숫자도 나오지만 그
숫자엔 "시간"이라는 뜻이 없다. 함수를 분리해 두면 그 순서를 강제하는
계약(entry point)이 하나 생긴다: 윈도우는 표집 이전, 원본 연속 행렬에만
쓴다. `tests/test_teacher_window.py::test_must_be_called_before_subsampling_
not_after_reorder` 가 이 규칙을 어기면 무슨 일이 나는지 실측으로 남겼다
(뒤섞은 순서에 씌우면 "오래된 블록=최근 블록-4" 관계가 거의 깨진다 —
매칭율이 100%에서 10% 미만으로 떨어진다).

### 1-3. 인과성 보장 — 구조로, 그리고 실측으로

구현(`window.py:104-111`):

```python
rows = np.arange(n)
lag = np.arange(window - 1, -1, -1)                     # window-1..0
raw_idx = rows[:, None] - lag[None, :]                   # (n, window)
clamped = np.maximum(raw_idx, session_start[:, None])    # 세션 시작 이전 금지
gathered = X[clamped]
```

`raw_idx <= i` 는 `lag >= 0` 이라 항상 참이고, `session_start[i] <= i` 도
항상 참이다. 둘의 최댓값이 `clamped` 이므로 `clamped <= i` 는 **테스트가
아니라 산술 그 자체가 증명**한다 — `window` 나 `session_ids` 가 무엇이든
미래 인덱스가 나올 수 없다. 그래도 사용자 지시("시간 윈도우에 미래 틱이
한 칸 섞이면 실험 전체가 무의미해진다")대로 실측 뮤테이션을 했다 —
`lag = np.arange(window-2, -2, -1)` (offset 을 하나 밀어 `i+1` 을 허용)로
바꾸면:

- 1차 시도는 배열 끝에서 `IndexError` 로 즉시 죽는다(너무 뻔한 버그).
- **"들키지 않는" 버전**을 다시 만들어(`clamped = min(clamped, n-1)` 로
  경계만 클립) 재시험했다 — 이건 크래시 없이 조용히 마지막 행을 제외한
  모든 행에서 `i+1` 을 훔쳐본다. `test_no_future_leakage_via_corruption` 이
  이걸 잡았다(과거 시점 행 111의 윈도우가 오염된 미래 행 112 때문에 달라짐,
  `assert_allclose` 3/3600 원소 불일치로 실패). §7 표 #1.

세션(종목) 경계도 인과성의 일부로 다뤘다 — 다른 종목의 역사를 빌리는 것도
누설이라고 보고, `session_ids` 로 준 **연속 런(run)** 을 세션 경계로 삼아
`session_start` 를 계산한다. 부족한 초반부는 **그 세션의 첫 행을 반복**해
채운다(0 패딩이 아니다 — 0 은 "평균적인 시장 상태"를 지어내지만 반복은
"그 시점엔 그 관측이 최선이었다"는 사실 그대로다).

### 1-4. 실측에서 발견한 두 번째 간극 — 비유한(non-finite) 과거값

`manifold.select` 는 **행 i 자신**의 feature 가 비유한이면 그 행을 표집에서
뺀다. 하지만 윈도우는 i 의 **과거** 행도 끌어오고, 과거 행은 그 필터를
통과한 적이 없다. 실데이터(20260316, 12종목)로 확인하니 전체 행의 **약
4.2%**가 비유한이었다(`ofi_over_qbar_5`, `bid_l1_depth_over_qbar` 등
유동성-분모 비율계 열 — qbar 가 0 에 가까워지는 순간). window=16 이면
"현재 행은 유한하지만 과거 16개 중 하나가 비유한"일 확률이 대략
`1-(1-0.042)^16 ≈ 50%` — 첫 실전 비교 실행에서 정확히 이 이유로
`DeepLOBCompact` 의 손실이 전부 NaN 이 됐다(`r2_path=-inf` 로 재현, §5-1).

**고친 방법**: `window.py::_forward_fill_non_finite` — 열별로, 세션 안에서만,
비유한 값을 **직전 유한값**으로 채운다(세션 경계는 넘지 않는다). 세션 시작
이후 한 번도 유한값이 없었으면(실측: 12종목 어디서도 이 경우는 없었다) `0.0`
폴백. forward-fill 은 오직 과거(`np.maximum.accumulate` 가 만드는 누적
최댓값)만 쓰므로 인과성을 깨지 않는다 — `test_forward_fill_is_causal_under_
future_corruption` 으로 재확인했고, 세션 경계를 무시하는 뮤테이션도
`test_forward_fill_does_not_cross_session_boundary` ·
`test_leading_non_finite_falls_back_to_zero_...` 둘 다 잡았다(§7 표 #6).

## 2. 병목 — 계약 준수

`DeepLOBCompact.bottleneck` 은 생성자 인자를 그대로 담고, `z()` 는 항상
`(n, bottleneck)` (`bottleneck` 을 1·2·5 로 바꿔 가며 확인,
`test_bottleneck_dimension_cannot_be_bypassed`). `predict_path`/`predict_fill`
두 헤드는 독립된 `nn.Linear(bottleneck, 1)` 이고, `ShallowMLP` 와 같은 자리에
같은 형태의 L1 벌점(`loss + l1 * latent.abs().mean()`)이 걸린다. `sd/teacher/
base.py` 의 `Teacher` Protocol 시그니처는 한 글자도 바꾸지 않았다.

## 3. 원 DeepLOB 에서 무엇을 뺐고 왜인가

| # | 원본 요소 | 이 구현 | 이유 |
| --- | --- | --- | --- |
| 1 | 레벨-압축 컨볼루션(`kernel=(1,2), stride=(1,2)`, 가격·수량 페어를 레벨 순서로 반씩 접는다) | **없음** — feature 축은 시간 컨볼루션의 채널로만 쓴다 | 입력이 원시 `(가격,수량)` 페어의 레벨 순서 텐서가 아니라 Catalog 가 계산한 feature 벡터고, 열 순서는 **알파벳 정렬**(`FEATURE_ORDER = tuple(sorted(...))`, `sd/ticks.py:18`)이다. "인접한 두 열이 인접한 호가 레벨"이라는 전제가 아예 없다 — 그 전제 위에서만 뜻이 있는 연산을 그대로 옮기면 무관한 값끼리 섞는다 |
| 2 | Inception 모듈(32~64채널 가지를 여러 깊이로, 레벨 압축 뒤에 3회) | 가지당 `inception_channels`(기본 4) 채널, 깊이 1(`_InceptionLite`) | "여러 시간 스케일(1·3·5 틱, 풀링)을 한 층에서 본다"는 구조적 특징만 보존. 병목이 이미 좁아(S1) 그 앞 표현력을 키워도 L1 이 결국 짓누른다 |
| 3 | LSTM 64, 단일/다층 | LSTM 16(`lstm_hidden`), 단일층 | 병목 뒤엔 좁은 선형 헤드 둘뿐이라 LSTM 자체를 넓힐 이유가 없다 |
| 4 | 3-class 분류 헤드(상승/보합/하락) | **없음** | 이 저장소의 계약은 스칼라 회귀(`predict_path`) + 체결확률(`predict_fill`) 두 헤드(`base.py`). 원본의 분류 문제 자체가 이 태스크에 없다 |
| 5 | BatchNorm(레벨 압축·Inception 각 층) | **없음** — `_standardise`(평균/표준편차)만 | 이 저장소는 미니배치를 쓰지 않는다(`ShallowMLP` 그대로 full-batch). 배치가 하나면 BatchNorm 은 표준화의 재탕이고, on-manifold 표집 후 표본이 수천 행 · 가중치가 불균등(`_tail_weight` `[1,5]`)이라 배치 통계가 흔들리기 쉽다 |
| 6 | 시간 윈도우 100스텝 | 기본 16(가변) | 100스텝은 원 논문의 (매우 조밀한) 호가 갱신 빈도를 전제한다. 이 파이프라인은 표집·가중치가 이미 다른 층에서 처리하고, 비교 실험 규모(§5)에서 계산 예산을 고려해 줄였다 — 원리적 상한은 아니다 |

**의도적으로 유지한 것**: `ShallowMLP` 와 같은 표준화(`_standardise`) 방식,
같은 자리의 L1 병목 벌점, 같은 옵티마이저(Adam)·같은 시드 배선 방식, 같은
두 손실(가중 MSE + 가중 BCE) 조합 — "무엇이 바뀌었는가"를 헤드 개수처럼
단일 축으로 남기기 위해서다(`sd/teacher/shallow.py` 자체 docstring이 이미
이 원칙을 `ShallowMLP` 에 대해 명시하고 있다).

## 4. 시간 윈도우가 실제로 값을 하는가 — 배관 검증

합성 데이터로 직접 확인했다(`test_deeplob_recovers_a_lagged_signal_that_needs_
history`): `y_path[i] = 3 * raw[i-5]` (타깃이 **현재가 아니라 5틱 전** 값에만
의존, 현재 행 자신의 feature 에는 이 정보가 없다).

| 조건 | corr(예측, 정답) |
| --- | --- |
| `window=12` (실제 과거를 봄) | **0.90+** (epochs=400, seed=7 재현) |
| `window=1` (현재 행만 — `ShallowMLP` 급 정보량) | **< 0.3** |

차이 0.3 이상을 assert 로 고정했다 — "윈도우를 무시하고 마지막 시점만 쓰는"
퇴화(축소된 능력으로도 다른 테스트는 다 통과할 수 있는 사례)를 이 테스트가
전담해서 잡는다.

## 5. ShallowMLP vs DeepLOBCompact — 비교표

**데이터**: 20260316, 층화 슬라이스 12종목(`per_stratum=2`,
`universe.slice_symbols` 그대로) — `000020·000040·000050·000070·000080·
000087·000100·000105·000120·000140·000180·000240`. 공통 무차원 feature 19개.
행 66,450 · 학습 가능 66,273. `manifold.select(max_samples=4000, seed=0)` →
on-manifold 3,948행 — **이 표집은 base X(윈도우 없음)로 한 번만 계산해 두
교사 모두에게 완전히 같은 행·같은 가중치**를 줬다(공정성 핵심 — 다른 표본을
보면 비교가 아니라 다른 실험이다). `bottleneck=2`, seed=0, `window=16`
(DeepLOBCompact 만). 스크립트: `/tmp/.../scratchpad/compare_teachers.py`
(E0·`run_slice.py` 를 부르지 않는다 — S0~S2 를 이 스크립트 안에서 직접
재현했다. `sd.universe`/`sd.ticks`/`sd.dimensionless`/`sd.labels`/`sd.manifold`
전부 읽기만 하고 수정하지 않았다).

### 5-1. epochs=300 (첫 실행 — 실전에서 forward-fill 버그를 여기서 발견했다, §1-4)

| | ShallowMLP | DeepLOBCompact |
| --- | --- | --- |
| r2_path (vs 실측 y_path) | **0.1999** | 0.1714 |
| r2_fill (vs 실측 y_fill) | **0.3633** | 0.2537 |
| 학습 시간 | 7.4s | 24.0s |
| 파라미터 수 | 712 | 3,160 |
| z 분산비(max/min) | 11.42 | 3.33 |
| z 대각외 상관(평균, bottleneck=2라 유일값) | 0.557 | 0.974 |

### 5-2. epochs=700 (같은 데이터·같은 seed, 예산만 늘림)

| | ShallowMLP | DeepLOBCompact |
| --- | --- | --- |
| r2_path | 0.1830 | **0.3045** |
| r2_fill | 0.4200 | **0.4791** |
| 학습 시간 | 9.1s | 56.0s |
| z 분산비(max/min) | 12.03 | 3.92 |
| z 대각외 상관 | 0.588 | 0.956 |

### 5-3. 해석

- **같은 epoch 예산(300)에서는 ShallowMLP 가 근소 우위, 예산을 늘리면
  (700) DeepLOBCompact 가 두 헤드 모두 역전한다.** 원인은 아키텍처 자체의
  열위가 아니라 **co-training 수렴 속도** 로 보인다 — 뮤테이션 자기검토
  중(§7 #4 준비 과정) 직접 관찰했다: path(MSE, 스케일 큼)와 fill(BCE)을
  공유 인코더로 같이 학습시키면 DeepLOBCompact 는 초반 수백 epoch 을 거의
  path 에만 쓰고 fill 로짓이 0 근방에 오래 머문다(같은 시드에서 epoch별
  corr_fill: 50→0.02, 350→0.09, 700→0.9998 — 실측 로그, §7-1 참고). 더
  깊은 인코더(conv→inception→LSTM)가 얕은 2층 MLP보다 그래디언트가
  전파되는 데 시간이 더 걸리는 것은 자연스럽고, 300 epoch 는 이 아키텍처엔
  아직 부족한 예산일 가능성이 높다. **"같은 epoch" 이 반드시 "같은 예산"은
  아니다** — 이 발견 자체가 비교표의 일부라고 본다.
- **z 의 성질이 뚜렷이 다르다.** ShallowMLP 는 bottleneck 두 축이 상대적으로
  덜 얽혀 있다(상관 0.56~0.59) — 두 축이 서로 다른 정보를 나른다는 뜻으로
  읽을 수 있다. DeepLOBCompact 는 두 축이 거의 하나로 뭉쳐 있다(상관
  0.95~0.97) — bottleneck 폭을 2로 줘도 사실상 유효 차원이 1에 가깝다.
  LSTM 최종 은닉 상태 하나가 이미 "가장 최근의 지배적 추세"라는 단일
  스칼라에 가까운 요약이 되기 쉽고, 그걸 다시 `Linear(lstm_hidden,
  bottleneck)` 으로 폭만 늘려도 두 축이 독립적으로 벌어지지 않은 것으로
  보인다 — **폭(width)과 유효 정보 차원(rank)은 다른 것**이라는 점을
  분명히 남긴다. 증류(distillation)가 실제로 저차원 다양체를 찾는 게
  목적이라면, DeepLOBCompact 의 z 는 그 점에서 오히려 "저차원성"에 더
  가깝다고도 읽을 수 있다 — 다만 이것이 좋은 신호인지 인코더가 두 번째
  축을 그냥 못 쓰고 있는 것인지는 이 실험만으로는 가릴 수 없다.
  `variance_ratio_max_over_min` 은 반대로 DeepLOBCompact 쪽이 더 균등하다
  (3.3~3.9 vs 11.4~12.0) — 두 신호(분산비·상관)가 서로 다른 각도를
  보여주므로 둘 다 표에 남겼다.
- **학습 시간은 예상대로 DeepLOBCompact 가 훨씬 오래 걸린다**(같은 epoch
  에서 약 3.2~6.2배 — 시스템 부하에 따라 배율이 변했다, 이 두 실행은 다른
  동시 부하 상황에서 쟀다). 파라미터 수는 4.4배(712→3,160) — LSTM·Inception
  분기 때문이지만, 여전히 원 DeepLOB(수십만~수백만 파라미터) 대비 매우
  작다.

## 6. 사전 예측과의 관계

사전등록 §3 은 "DeepLOB 으로 교사를 올려도 게이트 판정은 바뀌지 않는다"를
예측했다 — 근거는 v1 에서 교사 R² 와 법칙 복원 여부가 무관했다는 관측이다.
**이 보고는 게이트 판정 자체를 다루지 않는다**(E0 를 돌리지 않았다, 작업
지시). 다만 "DeepLOB 이 교사의 예측력(R²)을 실제로 바꾸는가"라는 선행
질문에는 값을 냈다: **바꾼다 — 그러나 오직 학습 예산을 늘렸을 때만, 그리고
그 폭은 크지 않다**(r2_path 0.18→0.30, r2_fill 0.42→0.48, 같은 종목·같은
표본·같은 seed). 이 R² 상승이 E0 게이트 판정에 어떤 영향을 주는지는 이
비교의 범위 밖이다 — 사전등록이 예측한 대로 "교사 R² 와 법칙 복원은
무관하다"가 맞다면, 이 정도의 R² 상승도 게이트를 흔들지 않을 것이라는
예측과 정합적이지만, 그건 E0 를 실제로 돌려야 확인되는 별개의 주장이다.
**이 값을 예측에 맞추거나 뒤집으려 하지 않았다** — 그대로 적는다.

## 10. 남은 우려

1. **DeepLOBCompact 의 co-training 이 ShallowMLP 보다 훨씬 느리게
   수렴한다**(§5-3). E0/본 실험이 고정 epoch 예산(`epochs=300`, PREREG
   §4 는 niterations 만 못박고 교사 epoch 은 안 건드렸다)을 그대로 쓰면
   DeepLOBCompact 가 불리하게 보일 수 있다 — 이건 "DeepLOB 이 더 나쁘다"가
   아니라 "예산이 아직 안 찼다"는 뜻일 가능성이 높다. E0 를 실제로 돌릴
   사람은 이 점을 감안해야 한다(내가 임의로 epoch 을 올려 통합하지는
   않았다 — 그건 "결과를 보고 설정을 바꾸는" 금지 사항에 해당할 수 있어
   비교표에만 두 조건을 나란히 남기고 판단은 위임한다).
2. **z 의 두 축이 거의 상관 1에 가깝게 뭉친다**(§5-3). `bottleneck=2` 를
   요청해도 실질적으로 유효 차원이 1에 가까울 수 있다 — S1 게이트나 H4
   ablation 이 "병목 차원 수"를 그대로 믿고 뭔가를 계산한다면 이 사실을
   알아야 한다. 이번 작업 범위에서 원인(구조적 한계 vs 학습 부족)을
   가르지는 못했다.
3. **`window=16`, `conv_channels=8`, `inception_channels=4`,
   `lstm_hidden=16` 은 계획서에 상한이 없어 내가 고른 기본값**이다(§3
   표 마지막 행) — E0 규모(niterations=200)에 맞는 값인지는 실측하지
   않았다. 비교 실행(§5)은 이 기본값 그대로 썼다.
2. **S1 게이트(`gate.py`) 확장을 하지 않았다.** `gate.py` 자체의
   docstring(내가 소유한 파일이지만 원래 있던 문구)이 "대칭성·스케일
   준불변·무시 변수 확인은 DeepLOB 교사가 들어올 때 추가한다"고 미리
   적어 뒀다. 이번 작업 지시엔 이게 없었고, `evaluate()` 의 판정 로직을
   건드리면 `run_slice.py` 의 `gate_result.passed` 판정 전체가 더
   엄격해져(이미 그 경로를 쓰는 파이프라인의 동작을 바꾸는 것이라)
   범위를 벗어난다고 판단해 손대지 않았다. 필요하면 후속 작업으로 남긴다.
4. **비교표(§5)는 12종목·표집 3,948행 규모다.** 이건 "교사 단독 비교"
   지시에 맞춘 가벼운 슬라이스이지 E0/본 실험 규모(전종목)가 아니다 —
   숫자의 절대값보다 "같은 조건에서 두 교사가 다르게 행동한다"는 상대적
   비교로 읽어야 한다.
5. **`_forward_fill_non_finite` 의 0-폴백 분기는 실측 데이터에서 한 번도
   발동하지 않았다**(12종목 어디서도 세션 첫 행이 비유한이지 않았다) —
   테스트는 합성 데이터로 그 분기를 강제로 태웠지만, 실데이터로는 발동
   경로 자체를 확인 못 했다. 분기 로직은 간단해 위험은 낮다고 본다.
